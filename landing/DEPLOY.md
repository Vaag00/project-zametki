# Запуск сайта на своём сервере

Сайт, админка, запись и бот Telegram работают на одном арендованном сервере (VPS) в России —
так данные клиентов хранятся в России, как требует закон о персональных данных.
Всё запускается одной командой через Docker, HTTPS-сертификат выпускается автоматически.

**Что понадобится:** сервер за ~200–500 ₽/мес, бесплатный домен (шаг 2) и около часа времени.

---

## 1. Сервер

1. Арендуйте VPS у российского хостинга — например, Timeweb Cloud, Selectel или REG.RU.
   Достаточно минимального тарифа: 1 ядро, 1–2 ГБ памяти, 15+ ГБ диска, **Ubuntu 24.04**.
2. Хостинг пришлёт IP-адрес и пароль. Подключитесь к серверу:

   ```bash
   ssh root@<IP-адрес>
   ```

3. Установите Docker:

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

## 2. Домен

### Бесплатный: DuckDNS (5 минут)

Адрес будет вида `vaag-ph.duckdns.org` — бесплатно и без срока. HTTPS работает так же, как на купленном домене.

1. Откройте [duckdns.org](https://www.duckdns.org) и войдите через Google или GitHub.
2. В поле **sub domain** впишите имя, например `vaag-ph`, и нажмите **add domain**.
   Если имя занято — попробуйте другое: `vaagph`, `vaag-photo`…
3. В строке нового домена в поле **current ip** впишите IP-адрес сервера и нажмите **update ip**.
4. Проверьте на своём компьютере (через минуту):

   ```bash
   ping vaag-ph.duckdns.org
   ```

   В ответе должен быть IP вашего сервера.

В `.env` на шаге 4 впишите этот адрес:

```
DOMAIN=vaag-ph.duckdns.org
SITE_URL=https://vaag-ph.duckdns.org
```

Адрес `www.vaag-ph.duckdns.org` тоже заработает и будет перенаправлять на основной.

### Свой домен (если купите)

Домен `.ru` стоит примерно 200–900 ₽ в год (REG.RU, RU-CENTER, Timeweb). Его можно подключить в любой момент:

1. У регистратора создайте DNS-записи:

   | Тип | Имя | Значение |
   |-----|-----|----------|
   | A   | `@`   | IP-адрес сервера |
   | A   | `www` | IP-адрес сервера |

2. Поменяйте в `.env` `DOMAIN` и `SITE_URL` на новый домен.
3. Пересоберите: `docker compose up -d --build`. Caddy сам выпустит сертификат на новый адрес.

## 3. Бот Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя, например «VAAAAAAG Запись».
2. Он пришлёт **токен** вида `123456789:AA…`. Это пароль бота — никому не показывайте.
3. Chat id узнаете на шаге 5: бот сам его пришлёт.

## 4. Код и настройки

На сервере:

```bash
git clone https://github.com/vaag00/project-zametki.git
cd project-zametki/landing
cp .env.example .env
nano .env
```

Если репозиторий закрытый, `git clone` спросит логин и пароль: вместо пароля нужен токен
(GitHub → Settings → Developer settings → Personal access tokens → Fine-grained, доступ только на чтение этого репозитория).

Заполните в `.env`:

- `DOMAIN` и `SITE_URL` — ваш домен из шага 2;
- `ADMIN_PASSWORD` — пароль для входа в админку (длинный, не как от почты);
- `TELEGRAM_BOT_TOKEN` — токен из шага 3.

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`).

Перед запуском впишите свои данные в политику конфиденциальности:
`PRIVACY_OPERATOR` в `src/App.tsx` (ФИО, статус и ИНН, почта) — сейчас там заглушки в квадратных скобках.

## 5. Запуск

```bash
docker compose up -d --build
```

Первый запуск — несколько минут. Потом откройте свой адрес, например `https://vaag-ph.duckdns.org`, — сайт работает.

**Подключите бота к себе:** найдите своего бота в Telegram и напишите ему `/start`.
Он ответит «Ваш chat id: 123456789». Впишите это число в `.env`:

```
TELEGRAM_OWNER_CHAT_ID=123456789
```

и перезапустите:

```bash
docker compose up -d
```

Напишите боту `/start` ещё раз — он ответит «Новые заявки будут приходить сюда».

## 6. Проверка

- Откройте `https://<ваш-адрес>/#admin` и войдите с паролем из `.env`.
- Оформите тестовую запись на сайте — заявка придёт в Telegram с кнопками «Подтвердить» и «Отменить»
  и появится в админке. Потом удалите её в админке.
- Отправьте ссылку на сайт себе в Telegram — должно появиться превью с картинкой.
- Откройте сайт с телефона и пролистайте до конца.

## Админка

`https://<ваш-адрес>/#admin` — вход по паролю `ADMIN_PASSWORD`.

| Вкладка | Что там |
|---------|---------|
| Заявки | Все заявки: подтвердить, отменить, удалить. Ссылка на контакт клиента открывает его Telegram или телефон. |
| Расписание | Время окошек, рабочие дни, на сколько дней вперёд открыта запись. Закрыть день (отпуск) или отдельное время. |
| Прайс | Пакеты: название, цена, что входит. Можно добавить новый пакет, скрыть или поменять порядок. |
| Портфолио | Серии и фото: загрузить (можно сразу несколько), подписать, поменять порядок, удалить. Первое фото — обложка серии. |

## Как работает запись

1. Клиент выбирает пакет, дату и свободное время, оставляет контакт и отмечает согласие на обработку данных.
2. Окошко сразу становится занятым для остальных. Вам приходит сообщение от бота с кнопками.
3. Клиент видит страницу статуса заявки и может нажать «Уведомления в Telegram» — тогда бот напишет ему,
   когда вы подтвердите или отмените съёмку.
4. Отмена (кнопкой в Telegram или в админке) освобождает окошко.

Если Telegram был недоступен, заявка всё равно сохраняется, а бот повторяет отправку каждые несколько секунд.

## Обслуживание

**Резервная копия** (база и все фото) — вручную:

```bash
docker compose exec app python -m app.backup
```

Копии лежат в `/data/backups` внутри тома `data`, хранятся последние 14.
Каждую ночь автоматически — добавьте в `crontab -e`:

```
0 4 * * * cd /root/project-zametki/landing && docker compose exec -T app python -m app.backup
```

Скачать копии себе на компьютер:

```bash
docker compose cp app:/data/backups ./backups
scp -r root@<IP-адрес>:project-zametki/landing/backups .
```

**Обновить сайт** после изменений в коде:

```bash
cd ~/project-zametki/landing
git pull
docker compose up -d --build
```

База и загруженные фото при этом сохраняются (они в томе `data`).

**Посмотреть логи**, если что-то не работает:

```bash
docker compose logs -f app
```

## Для разработки (на своём компьютере)

```bash
# сервер
cd landing/server
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
ADMIN_PASSWORD=dev TELEGRAM_POLLING=0 .venv/bin/uvicorn app.main:app --reload    # http://localhost:8000/api
.venv/bin/python -m pytest                                                        # тесты

# сайт — в другом окне, в папке landing
npm install
npm run dev     # http://localhost:5173, запросы /api уходят на сервер
```
